# Medium layout recommendations: source-backed guidance

This reference records guidance from the linked Medium documentation and the historical editor observations in `editor-capabilities.md`. Check the relevant current source or live editor before relying on a platform limit, format rule, or distribution policy. The layout patterns are optional editorial recommendations, not guarantees of reach.

## Recommended article shape

1. **Header:** use a precise title, an explanatory subtitle when it adds context, and an optional kicker only when it helps orient the reader.
2. **Opening:** give the reader the problem, promise, or point of view quickly. If there is a meaningful cover visual, place it where it supports this opening; omit it rather than use generic decoration.
3. **Body:** use primary headers for major arguments and secondary headers only for genuine subsections. Keep paragraphs short enough to scan, but let technical reasoning retain the detail it needs.
4. **Visuals:** place a diagram, chart, or annotated screenshot immediately after the claim it explains. Add accessible alt text and a plain caption that states why the visual matters.
5. **Close:** end with the implication, a practical checklist, or a clear next step rather than a generic recap.

## Image decisions

- Earlier Medium guidance specified at least 1192px of width for all image placement options. Check the current requirement when those options matter.
- Earlier guidance listed `.jpg`, `.jpeg`, `.gif`, and `.png` with a 25 MB file limit. Check the current upload constraints and available controls rather than treating these values as timeless.
- Prefer one strong cover and a small number of explanatory visuals to a stream of decorative stock images. Medium's distribution guidance explicitly says that no cover is better than a poorly chosen one.
- Use an image grid only for comparison sets, step sequences, or a photo essay. Medium automatically orders a multi-file upload alphabetically by filename; rename files in their intended order and inspect the generated grid.
- Add credits where appropriate. Do not assume caption italics are supported; Medium says captions cannot be italicized.

## Blocks and embeds

- Use lists for procedures, trade-offs, or checklists. Medium supports bulleted and numbered lists, but a numbered list cannot continue after a section break or between images.
- Use a quote block for an actual quotation or a deliberately isolated central claim, not as a decorative paragraph style.
- Use a code block for public code; Medium supports a new-line `{ }` control or triple-backtick shortcut, plus inline code with single backticks.
- To embed supported external content, paste its direct `http` or `https` URL on a new line and press Enter. Do not use embed code. Unsupported URLs become preview cards rather than interactive embeds.

## Distribution and credibility

- Make the title, subtitle, and cover image specific and representative, not clickbait, vague, or formulaic.
- Use illustrations, headings, and document structure to improve readability. Images should add value, include alt text, and have appropriate credits.
- Do not claim that any format guarantees wider distribution. Medium evaluates overall craftsmanship, originality, reader value, and policy compliance.
- Earlier Medium guidance excluded stories appearing to be generated by AI from Boost or General Distribution. Consult the current distribution guidelines when eligibility matters, accurately describe any applicable limitation, and preserve truthful authorship. Do not promise reach or add an unrelated approval step to ordinary drafting.
